# 한보금on 활동지원 (저장소 kif · 옛 이름: mirae-bohum, 한국보험금융 교육지원 포털)

FC 영업지원·교육지원 포털. GitHub Pages로 배포됩니다: https://bluewind1124-ui.github.io/kif/

이 폴더가 **포털과 하위 프로그램 전체의 기준(원본)** 입니다. 개발·수정은 모두 여기서 하고, 같은 내용을 GitHub 저장소에 올려 배포합니다.

## 폴더 구조

## 메뉴 연결 (index.html)

- 영업 도구: 상품 비교 · **AI보장분석 기본형**(`ai`) · **AI보장분석 고급형**(`ai2`) · 대표 상품 가설 · 이달의 컨셉
- 교육: 온라인 교육센터 · **AI보장분석 고급형**(`ai2`)
- 고급형 페이지(`PAGES.ai2`)는 `advanced/index.html`을 iframe으로 띄우고 「새 창으로 크게 열기」를 제공합니다.
- 포털 로그인 시 `sessionStorage.fc_portal_ok=1`을 남기고, 고급형은 포털 안이거나 이 값이 있을 때만 열립니다. 직접 주소로 열면 포털 로그인으로 안내합니다. (점검용: `advanced/index.html?standalone=1`)

## 로그인 · 계정

- 계정 서버 주소(`content.json`의 `authApi`)가 있으면 개인 계정으로만 로그인합니다. 없으면 시제품 체험용 계정(fc1001 · admin)으로 동작합니다.
- 로그인 화면: 로그인 · 계정 신청(관리자 승인 후 사용) · 비밀번호 찾기(관리자에게 초기화 요청)
- 관리자 페이지 「FC 계정 관리」: 승인·거절, 임시 비밀번호 발급, 정지·다시 사용, 권한 변경, 삭제, 직접 발급
- 「내 정보」: 비밀번호 변경(지금 비밀번호 확인 후 바로), 고객 자료 보관(내 PC·내 클라우드에 파일로 저장·불러오기)
- 포털 로그인 한 번으로 상품 비교(`classic/`)와 AI보장분석 고급형(`advanced/`)이 바로 열립니다(같은 사이트의 `localStorage.kif_sso`, 12시간). 접속코드는 없앴습니다.
- 고객 자료는 계정 서버에 올리지 않습니다. 각 기기 브라우저와 사용자가 고른 PC·클라우드 파일에만 있습니다.

## 자료 올리기 (관리자 페이지)

- 파일(PDF·PPT·엑셀·워드·한글·사진)을 넣으면 메뉴(보험사 소식지 · 본사 공지 · 시상 공지 · 이달의 컨셉 · 대표 상품 가설 · 교육 자료)를 파일 이름·첫 장 글자로 판단합니다. 소식지는 회사·연월·주차를 읽어 「회사 연월 N주차 소식지」로, 나머지는 파일 이름으로 제목을 만듭니다. 요약은 PDF 첫 장의 글머리(▪)에서 뽑습니다.
- 「모든 FC에게 올리기」는 GitHub API로 파일과 `content.json`을 **main에 한 번에 커밋**합니다 (1~2분 뒤 사이트 반영). 처음 한 번 kif 저장소 전용 토큰(Contents: Read and write)을 관리자 브라우저에 저장해야 합니다.
- `content.json` 줄 형식 (마지막 칸이 파일 경로, 비어 있으면 글만 표시):
  소식지 `[날짜, 회사, 요약, 파일, 제목]` · 공지 `[날짜, 내용, 파일]` · 시상 `[제목, 기간, 내용, 상태, 파일]` · 가설 `[고객 유형, 대표 상품, 첫 화법, 파일]` · 교육 자료 `[종류, 제목, 분류, 설명, 파일]` · 컨셉 `concept.file`, `concept.mats[종류, 제목, 파일]`
- 소식지·공지는 보관 기간(기본 3개월)이 지나면 다음 올리기 때 파일과 줄을 함께 지웁니다.
- 올린 파일은 공개 사이트 주소로 누구나 열 수 있습니다. 고객 정보가 든 자료는 올리지 않습니다. 저장소 전체 1GB 이내를 유지합니다.

## 관리 규칙

1. 원본은 이 폴더 하나. 다른 위치에 복사본을 두고 고치지 않습니다.
   - 포털에 생기는 모든 수정·추가(아이콘 포함)는 새로 만들지 않고 이 저장소(kif)의 같은 파일을 고쳐 실제 사이트에 바로 반영합니다. 이름·아이콘이 바뀌면 icon-*.png · og-image.png · desktop-icon.zip · manifest · 설치 안내 그림(install-guide.png, 바탕화면 배포용_설치안내)을 함께 바꿉니다.
2. 고급형을 고치면 `docs/AI보장분석_고급형_생성기록.md`에 버전과 내용을, 포털 변경은 `version.json`의 `history`에 한 줄을 추가합니다.
3. 세법·법령 수치는 고급형 「기준 설정 → 세법 기준표」와 「법령·세법 점검」으로 관리합니다 (`docs/법령·세법 업데이트 설명서.md`).
4. 배포할 때마다 `version.json`의 `build`와 `index.html`의 `<meta name="kif-build">` 값을 똑같이 올립니다. 포털이 열릴 때 둘이 다르면 저절로 새 화면을 불러옵니다(브라우저 10분 기억 문제 해결).
5. 배포: GitHub 저장소 `bluewind1124-ui/kif`의 `main` 브랜치에 올리면 GitHub Pages에 반영됩니다. 배포 전 작업은 별도 브랜치에 올려 둡니다.
5. 고객 자료는 각 FC 브라우저(localStorage)에만 저장됩니다. 저장소에 고객 정보나 대화 기록을 올리지 않습니다.
