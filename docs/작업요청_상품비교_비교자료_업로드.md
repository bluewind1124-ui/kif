## 결정된 사항 (2026-10-24, 사용자 확인)

- 「확인할 것」의 답: **2번 — AI로 읽어 비교표 숫자까지 자동 갱신.** 원본 파일만 올려 열람하는 방식은 하지 않는다.
- 5종 도구는 원픽과 다르다. 원픽은 AI가 선정 상품·선정 이유까지 쓰지만, 5종 도구는 **화면에서 고른 옵션(나이·성별·납입기간·심사 등)에 맞춰 데이터를 정렬해 1·2·3위를 자동으로 매기는 구조**다(각 도구의 `has.sort(...)` → `.rank` 카드). 순위를 따로 저장한 곳은 없다.
  → 따라서 **AI는 올린 자료의 숫자·상품명·조건만 읽어 `DATA`를 새로 채우고, 순위는 지금처럼 도구가 자동으로 매긴다.** AI에게 순위·선정 이유를 만들게 하지 않는다.
- 사용자 말: "원픽을 제외한 자료는 올리면 자동으로 1,2,3번째로 또는 주어진 옵션에 따라 설정되는 방식이었어." (포털에 합치기 전 프로그램 = 2026-10-16에 `classic/`으로 옮긴 파일들로 확인함. PC에 따로 보관한 예전 파일이 있으면 그것도 대조할 것.)
- 이전 자료는 보관하지 않는다(도구마다 최신 1건).

## 배경

관리자 페이지 「상품 비교」에는 **이번 달의 원픽** 입력 화면(가이드 PDF 올리기 → AI로 읽기 → 비교표 갱신)만 있다.
나머지 비교 도구 5종은 매달 자료가 바뀌는데, 새 자료를 올리는 화면이 없다.

| id | 메뉴 이름 | 화면 파일 |
|---|---|---|
| `life` | 생명보험 가이드북 비교 | `classic/life.html` |
| `nonlife` | 담보별 비교견적 | `classic/nonlife.html` |
| `wholelife` | 단기납 종신보험 비교 | `classic/wholelife.html` |
| `critical3` | 3대질병진단비 비교 | `classic/critical3.html` |
| `ceoterm` | 경영인 정기보험 비교 | `classic/ceoterm.html` |

(목록 기준: `index.html`의 `CMP_BASE`, 메뉴 정의 `['상품 비교',[…]]`)

## 해야 할 일

1. **관리자 › 상품 비교 아래에 「비교자료 업로드」 화면 추가**
   - 위 5개 항목을 한 화면에 카드(또는 표)로 나열한다.
   - 항목마다: 파일 올리기(PDF·엑셀·PPT·그림) · 기준월(연.월) · 마지막 올린 날짜 표시 · 열어보기 · 지우기.
   - 「이번 달의 원픽」 입력 화면과 같은 묶음(상품 비교)에 둔다.
2. **업데이트하면 이전 자료는 보관하지 않는다**
   - 새 파일을 올리면 이전 파일은 저장소에서 지우고 교체한다(원픽의 `onepicks` 같은 지난 자료 보관 없음).
   - `content.json`에도 항목별로 최신 1건만 남긴다.
3. **자료 관리와 연동**
   - 관리자 › 자료 관리 「상품 비교」 탭(`CM_TABS`의 `compare`)에서 같은 자료가 보이고, 거기서 교체·지우기를 해도 비교자료 업로드 화면에 그대로 반영된다(반대도 같음).
   - 파일을 두 군데 따로 저장하지 않는다. 한 곳(`content.json`의 항목 + 파일 1개)을 함께 본다.
   - 커밋 방식은 기존 「모든 FC에게 올리기」(GitHub API, main 한 번에 커밋)를 그대로 쓴다.
4. **FC 화면 반영**
   - FC가 상품 비교 › 각 도구를 열었을 때 그 달 비교자료(원본 파일)를 열어볼 수 있게 한다(예: 도구 화면 위쪽 「이번 달 원본 자료 · 기준월」 버튼).
5. **건드리지 않을 것**
   - 「이번 달의 원픽」 입력·AI 읽기·지난 원픽 보관 기능은 지금 그대로 둔다.
   - 한국보험금융 톤앤매너(남색 #0F2340 · 금색 #CD9B34)와 기존 관리자 화면 모양을 따른다.

## 설계

### 저장 방식 (도구마다 최신 1건)
- `content.json` → `cmpdata: { life: {month:"2026.11", upd:"2026.11.03", title:"원본 이름", file:"files/cmpdata/…pdf", data:"classic/data/life.json", ver:"<저장 시각>", at:"YYYY-MM-DD"}, nonlife:{…}, … }`
- `classic/data/<도구>.json` = 그 도구의 `DATA` 전체(지금 각 html 안의 `DATA`와 **같은 구조**). 경로는 고정, 새로 저장하면 덮어쓴다.
- 원본 파일은 바꾸면 이전 파일을 `CM.del`로 지운다(원픽 「파일 바꾸기」와 같은 방식). 지우기 = 원본 파일 + `classic/data/<도구>.json` + `cmpdata[도구]` 삭제 → 도구는 html 안의 기본 `DATA`로 돌아간다.
- 커밋은 기존 `KIFPUB.patch`(GitHub API, main 한 번에). `cmIsRepo()`에 `classic/data/` 경로를 추가해야 지우기가 된다. `cmsCollect()`의 SITE 보존 키 목록(`['compare','off',…]`)에 `'cmpdata'`를 넣는다.

### 도구 쪽 (✅ 완료 — 커밋 66e4fc0)
- `classic/cmpdata.js` 추가: `KIFCMP_LOAD(id, DATA)`가 `../content.json`의 `cmpdata[id]`와 `../classic/data/<id>.json`을 동기 XHR로 읽어 `DATA`를 바꾼다(빠진 최상위 키는 기본값으로 채움). 실패하면 기본 `DATA` 그대로.
- 관리자 「미리 보기」: 같은 브라우저 `localStorage.kif_cmpprev_<id>` = `{exp, data, month, upd, file, title}`(2시간)이 있으면 그것을 먼저 쓰고 「미리 보기 · 아직 저장 전」 표시.
- 5개 html: `const DATA` → `let DATA`, 바로 뒤에 `if(window.KIFCMP_LOAD)DATA=KIFCMP_LOAD('<id>',DATA);`, 앞에 `<script src="cmpdata.js?v=20261024a">`.
- `header.app`에 「○○○○.○○ 자료 기준 · 업데이트 날짜 · 📎 이번 달 원본 자료 보기」 표시. 머리말의 `(26.09)`·`U/W 2026.09.04` 글자를 새 기준으로 바꾼다.
- 원본 보기는 포털 안이면 `postMessage({kif:'mat', file, title})` → **포털 index.html에 이 메시지 처리(openMat) 추가 필요(아직 안 함).** 기존 `kif:'pdf'`는 PDF만 받으므로 따로 둔다.

### 관리자 화면 (⬜ 할 일)
- 자료 관리 탭에 **「비교자료 업로드」**(`cmpdata`)를 「이번 달의 원픽」 바로 뒤에 추가(`menuSync()`의 `CM_TABS` 구성, `CM_HELP`, 탭 숫자, `cmHtml`/`cmSave`의 분기, `cmW()`에 `cmpdata`).
- 도구 5개를 카드로: 기준월 · 업데이트 · 원본 파일(📎 열기/파일 바꾸기) · 「AI로 읽어 표 새로 만들기」 · 진행 상황 · 「미리 보기」 · 「이 내용으로 바꾸기」/「버리기」 · 지우기.
- 「상품 비교」 탭(`cmCompare`)의 기본 도구 카드에도 같은 `W.cmpdata[id]`를 보여 주고 바꾸기·지우기 버튼 → 같은 데이터라 양쪽이 저절로 맞는다. 지금 있는 「내용을 바꾸려면 새 HTML로 파일 바꾸기」 안내 문구는 「비교자료 업로드」 안내로 바꾼다.
- FC 화면: `cmpPage()`의 도구 위 막대(`ai-adv-bar`)에 「📎 이번 달 원본 자료 (기준월)」 버튼 추가.

### AI로 읽기 (⬜ 할 일) — 한 번에 못 읽으므로 나눠 읽는다
- AI 출력 한도(Claude 16,000토큰, `ai-connect.js` `apiCall`) 때문에 `DATA` 전체(life 116KB · nonlife 약 500KB · critical3 97KB)를 한 번에 만들 수 없다. **단위별로 나눠** 부른다.
  - life: `sections`의 18개 항목 + `details`(작아서 한 번에) + `meta`
  - nonlife: `groups` 26 · `totalGroups` 2 · `infoGroups` 15 · `coverDetail` 4 · `silson`·`ref_bojong`·`ref_hando`·`desc`·`catExtras`·`meta` (작은 것은 묶어서 약 12KB 이하로)
  - wholelife: `sets` 9 + `overview`/`overviewCompanies`/`meta`
  - critical3: `sets` 6 — 가장 큰 것 38KB이므로 `rows`를 여러 묶음으로 나눔(새 상품 줄은 마지막 묶음에서만 추가하라고 지시)
  - ceoterm: `sets` 12 + `overview`/`overviewCompanies`/`meta`
- 순서: ① 자료 글자 뽑기(PDF는 index.html의 `pdfPages()`, 엑셀·PPT는 `KIFAI.read()`) → ② 쪽 찾기: 쪽마다 첫 몇 줄 + 단위 제목 목록을 AI에 주고 "단위별로 해당 쪽 번호"를 받는다(실패하면 단위의 `source`「가이드북 p.n」 근처 쪽) → ③ 단위마다 「지난 달 단위 JSON(구조 참고) + 해당 쪽 글자」를 주고 **같은 구조의 새 JSON**을 받는다(동시에 3개씩).
- 프롬프트 규칙(원픽 `opAi()`와 같은 원칙): 숫자·금액·상품명·회사명은 자료 그대로, 없는 내용은 지어내지 말 것, 키 이름·자료형(숫자는 숫자) 유지, 자료에서 사라진 회사·상품 줄은 빼고 새로 생긴 줄은 넣기, 순위·추천 문구는 만들지 말 것.
- 받은 답 점검: 지난 단위와 최상위 키 비교(빠진 키는 지난 값으로 채우고 표시), 배열·객체 모양 확인, **바뀐 값 개수·줄 수 변화**를 단위별로 보여 준다. 실패한 단위는 지난 값 그대로 두고 「다시 읽기」 버튼.
- 「복사·붙여넣기」 AI(`prov==='paste'`)는 수십 번 붙여넣어야 하므로 이 기능에서는 쓰지 않는다고 안내(회사 AI·내 키·Claude 화면 연결만).
- 확인 → 「미리 보기」(localStorage에 넣고 포털 안에서 도구 열기) → 「이 내용으로 바꾸기」 → `classic/data/<id>.json` 스테이징 + `cmpdata[id]` 갱신 → 「저장」.
